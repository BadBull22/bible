## 3. How releases work now

**The signing key.** `C:\Users\ErichT\.tauri\bible-concordance-updater.key` (no password).
Its public half is in `src-tauri/tauri.conf.json` → `plugins.updater.pubkey`. Installed copies
only accept updates signed with this key. **If it's lost, no installed copy can ever be
updated again.** Keep a backup off this PC and **never commit it** (it lives outside the
repository on purpose).

**To ship the next version:**

1. Bump the version in `package.json`, `package-lock.json` (lines 3 and 9),
   `src-tauri/Cargo.toml` and `src-tauri/tauri.conf.json`.
2. `npx tsc --noEmit`, `npx vite build`, and `cargo test` in `src-tauri`.
3. `pwsh -File scripts\release.ps1 -Notes "short summary"`. It checks the four versions
   match and sets the signing key for the build only. It then builds and copies the
   installers into `installer\`, renamed without spaces (GitHub turns spaces into dots, and
   `latest.json` must name the real file). It writes `latest.json` and lists every file with
   its SHA-256. Finally it **prints** the `gh release create` command; it never runs it.
   If the build fails in WiX `light.exe` with no message, run it again: that happened once,
   a transient file lock.
4. Install the new setup.exe over the old version and smoke-test it.
5. Commit and push (see section 5 for identity and staging), then run the printed
   `gh release create` command with a notes file. `gh release create` tags the current
   `master`, so push first.

`latest.json` sits at `releases/latest/download/latest.json`, so **the newest release must
always be a full app release with its own `latest.json`**. Never publish another kind of
release (for example a voice-only one) as "latest".

**The voice archive** only changes when the voice does. `src-tauri/resources/voice.json`
points at the copy attached to the **v2.4.0** release, and later releases keep using it.
For a new voice: rebuild it (`voice-sidecar\build.ps1`), run
`python scripts/package_voice.py --tag vX.Y.Z` (this rewrites `voice.json`), and upload the
new zip with that release. Bump `VOICE_VERSION` in the script so the file name changes.

**Each update downloads the whole installer** (~376 MB), because the Bible, commentary and
study databases are inside it. Moving them out the same way as the voice would cut updates
to about 20 MB (see section 7).

## 5. Git

- **Identity.** Commits must be `BadBull22 <BadBull22@users.noreply.github.com>`. The repo
  now has that set locally (`git config user.name/user.email`, in `.git/config`, not
  tracked), so a session that forgets the `-c` flags still can't leak the real address.
- **The real email is still in pushed commit `ac15e08`** (v2.3.0, 2026-10-01). The user
  chose to leave it out of the new work; the old commit was **not** rewritten, because that
  needs a force-push. If it should be purged later, follow the "email-exposure" section in
  `HANDOVER.md`: `git filter-branch --env-filter` on that commit, delete `refs/original/*`,
  expire the reflog, `gc --prune=now`, `git push --force-with-lease`. Note that rewriting
  moves the `v2.3.0` and `v2.4.0` tags' history too, so they'd need re-pointing, and GitHub
  may keep the old SHA reachable for a while.
- **Stage by explicit path, never `git add -A`.** `check/` holds copyrighted PDFs
  (gitignored, but don't risk it), and `installer/` is huge (also gitignored). Scan the staged
  diff for emails and keys before committing. The updater **public** key is meant to be
  public.

## 7. Open ideas (none started)

- **Smaller updates:** download the databases (bible.db 256 MB, commentaries.db 190 MB,
  study.db 77 MB, the search model 88 MB) on first run, like the voice, so the installer
  and each update shrink to the program itself.
- Septuagint (Swete); Doré's New Testament plates (another Commons category); Schnorr's
  *Bible in Pictures* (needs references).
- **Mac (deferred by the user):**
  - A Mac, or GitHub Actions macOS runners, to build on (Tauri can't build for macOS from
    Windows).
  - The gitignored databases and model made available to that build.
  - The voice sidecar rebuilt there. `server.py` watches its parent process in a
    Windows-only way. Then run `package_voice.py` there to add a `darwin-aarch64` entry.
  - An Apple Developer account ($99/year) to sign and notarize.
  - Someone with a Mac to test.
- **Phone app (deferred by the user):** Tauri 2 can target Android and iOS, but the app
  would need a phone layout, a smaller data set (the databases are about 600 MB), a
  replacement for the voice sidecar, and store accounts.
