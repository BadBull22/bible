## 4. Things learned today (so they aren't relearned)

- **Tauri versions:** the npm `@tauri-apps/*` packages must match the Rust crates' major.minor, or `tauri build` stops. Installing `@tauri-apps/plugin-dialog@latest` pulled `@tauri-apps/api` up to 2.12. They are now pinned: `plugin-dialog ~2.7.0`, `api` locked at 2.11.1.
- **A second window (the slide screen)** must be created from Rust with the main window's `additionalBrowserArgs`, or WebView2 hangs (`show_window_open`).
- **The emulator:**
  - An x86_64 APK won't install on a phone, which says "not compatible". For the owner's phone, always build `android.ps1 -Release` (arm64 + armv7, release key); it then installs as an update.
  - The emulator ran out of space; reinstalling there needs `pm uninstall` first.
  - Through the emulator's network, the phone couldn't read the computer's answer; the real phone was fine.
- **The owner's phone:**
  - USB debugging is on (Developer options) and this PC is authorised.
  - A release build has no WebView devtools, and `uiautomator dump` of the WebView goes stale. Use `adb exec-out screencap -p` with taps by coordinate (the screen is 1200×2652).
- **Git:** `git config --global --add safe.directory "%(prefix)///Private/Other/Code/bible"` was needed (the share's ownership). It's done on this PC; the other PC may need it too.
- **PowerPoint check:** the video extension uri is `{DAA4B4D4-6D71-4841-9C94-3DE7FCFB9230}`. PowerPoint COM (`Presentations.Open`, `MediaFormat.IsEmbedded`) checks it without a window. Only do this when PowerPoint isn't already open.

## 18. 2026-10-18: 2.9.3 for both apps — the search finds what the reader remembers

The owner found the phone's search weak: "Daniels prayer delayed" / "where was Daniels prayer
delayed by 21 days" found nothing useful on the phone, while the PC found Daniel 10:2. He asked
for an offline "search upgrade" (not to be called AI), a "Search online" button, and more topics.

- **`bible_core::find`** (new, shared by both apps), working out what a search means and ranking
  it:
  - **Spelling:** a misspelt word becomes the Bible's nearest word, using the fts5vocab word list.
  - **Possessives:** Daniels / Daniel's → daniel.
  - **Numbers:** 21 also matches "twenty one" and "21".
  - **Names:** a word the BSB nearly always capitalises; the chapters it appears in count ×3.
  - **`STORIES`:** 62 well-known stories by name (prodigal son, prayer delayed → Daniel
    10:1–14 …).
  - **Ranking:** RRF over exact phrase, all words, most words (common words left out), numbers,
    the meaning neighbours and the subject search.
    - Pinned on top, highest first:
      1. stories (20);
      2. exact wording (10 when the search has four or more words, otherwise 4);
      3. key passages (5; with a name in the search, only those in the name's chapters).
  - **Passages:** found verses are grouped into passages (gap ≤ 6, span ≤ 12, or a key passage's
    range).
  - **Speed:**
    - The BSB is rows 1–31086 in both databases, so the FTS queries are limited to that rowid
      range (`bsb_rows`).
    - Name detection samples 60 verses.
- **`bible_core::meaning`** (feature "meaning"):
  - all-MiniLM-L6-v2 with candle, and its own WordPiece tokenizer. It is identical to the
    tokenizer library on all 93,286 BSB, KJV and WEB verses.
  - The weights are packed to 8 bits per row (23 MB); the verse vectors are 8-bit with a scale per
    verse (12 MB).
  - The packed model's cosine with the full one is ≥ 0.9995; top-10 overlap 114/120 (ties).
- **The pack:** `src-tauri/src/bin/make_search_pack.rs` builds it and checks it. Zipped it is
  31 MB, published as GitHub release **`search-pack-v1`** (`advanced-search-v1.zip`,
  sha256 `48c9fcff…ca8abdb9`). The phone's `meaning_pack.rs` names that URL and SHA.
  - To rebuild:
    `cargo run --release --bin make_search_pack -- resources/bible.db resources/model <out>`,
    then zip the files with no folder.
